# TypeScript 工坊 · 产品规格

> 本文件保存项目需求与验收标准。原始需求来自项目发起人（下称“学习者”）提供的完整指令，并叠加其在同一对话中追加的四点要求（见 §2）。
> 规格创建日期：2026-10-20。实现进度见 [STATUS.md](STATUS.md)，里程碑见 [PLAN.md](PLAN.md)，课程图谱见 [CURRICULUM.md](CURRICULUM.md)。

## 1. 产品目标

构建一个可运行、可维护、免费开源的中文交互式 TypeScript 学习平台「TypeScript 工坊」：

- 学习者已会 Python / Java / C++，但没系统学过 JavaScript。从第一天就写 TypeScript，按需讲清 JS/TS 共用语法与运行语义。
- 路线：读懂并编写 TypeScript → 独立实现有交互、有测试、能部署的网站 → 理解并实践 React、Next.js 与基础全栈。
- 不宣传“保证精通”“涵盖全部知识”。

**核心验收（一句话）**：打开一节课，在同一页理解一个知识点、修改并运行代码、完成经过真实检查的小任务，刷新后继续学习，并最终沿着已发布主线做出和部署自己的网站。

### 1.1 学习节奏（最重要的偏好）

短篇讲解 → 讲解下方直接改代码、运行 → 一个小任务 → 下一个知识点 → 本课编程挑战与小测验。

不做：纯题库、视频课、长文 + 独立 Playground、只有编辑器与控制台的页面。

### 1.2 默认决策

- 简体中文界面与讲解；重要术语首次出现附英文；代码标识符用惯用英文。
- 桌面优先，兼顾平板与手机。
- AI 是开发工具与**可选**的答疑辅助，学习主流程不依赖它（见 §2）。

### 1.3 首期不做

商业化、支付、社交、排行榜、证书、多用户账号体系、实时协作、AI 教师代替课程。

## 3. 用户流程

1. **进入**：默认进入“继续学习 / 课程路线”页（无营销 Hero）。显示已发布数 / 规划数、各阶段进度、上次位置。
2. **选课**：左侧可折叠目录（阶段 → 课时），支持搜索；可直接进入任意已发布课；未满足先修时显示提醒但不锁。规划中/草稿课时显示为不可进入的条目并标注状态。
3. **学习一课**：
   - 顶部：学习目标、先修、解决的实际问题、审核状态。
   - 正文按“步骤”渲染：讲解段落 → 内嵌 Playground（运行/停止/重置、输出或网页预览、观察提示）→ 小任务（检查、提示、答案）→ 下一讲解……
   - 课末：编程挑战（规格、起始代码、验收测试、三级提示、参考解与解释）、2–4 道小测验（每个选项都有解释）、常见错误、下一步、参考资料（含检查日期）。
4. **状态**：每个练习区分 未开始 / 尝试中 / 运行过 / 类型正确 / 行为测试通过 / 已查看答案；编辑后旧的通过结果失效。课时区分 已阅读 / 进行中 / 完成。
5. **保存**：草稿自动保存到 IndexedDB；刷新恢复代码与上次位置；可重置单题；进度导出/导入（JSON）。
6. **同步（可选）**：在“设置 → 同步”输入同步密码后，进度与草稿在设备间同步；离线时照常本地保存，恢复联网后合并。
7. **问 AI（可选）**：在 Playground/练习旁打开“问 AI”，自动附带本步讲解、当前代码、诊断/输出；默认先给思路而非直接给答案。

## 4. 课程内容要求

### 4.1 每课结构

1. 学习目标、先修、实际问题。
2. 短段落解释一个知识点；必要时与 Python/Java/C++ 精准对比。
3. 原位可编辑示例：运行、停止、重置；输出/预览；说明要观察什么。
4. 立即动手的小任务（改条件、补函数、先预测再运行验证）。
5. 下一个知识点 + 示例（多数课 ≥ 2 次“解释→操作”循环；单概念短课不硬凑）。
6. 课末 ≥ 1 个独立挑战：清楚规格、起始代码、验收测试、逐级提示（方向 → 更具体 → 参考答案，均需主动展开）、参考解与解释。挑战题型混合：补全、修错、类型设计、从小规格实现。
7. 2–4 道有诊断价值的小测验（结果预测、找错、单/多选、简短代码题），选错也给原因。
8. 常见错误、下一步、已核实的官方参考（标检查日期，涉及版本的 API 标适用版本）。

### 4.2 质量规则

- 不未讲先考；不得把未教过的类型技巧作为唯一解法。
- 起始文件不含答案；答案不自动出现。
- 不把“点开页面”算作掌握。
- 不用固定字数灌水。
- AI 生成的讲解不得自动标为“已审核”。审核状态：`ai-draft`（AI 起草，经自动验证）→ `self-reviewed`（经过明确的二次检查）→ `reviewed`（人工审核）。
- 原创代码 MIT；原创课文 CC BY 4.0；第三方内容保留原许可与署名。

### 4.3 每个发布课时的验收

- 说明与所引权威资料一致；简化处说明边界。
- 每个示例在指定模式实际运行；预期错误示例按预期失败（按文件/位置/诊断码匹配）。
- 参考解通过类型、行为与交互测试。
- 起始代码不泄漏答案；未完成挑战不会无条件通过（起始代码必须判为未通过）。
- 至少两个针对教学目标的常见错误解被正确拒绝（不适用时记录原因）。
- 至少一个不同写法但同样正确的解可通过。
- 测验答案与解释逐项核对；练习依赖的知识已出现（先修检查）。

### 4.4 课程范围（完整目标，分阶段实现）

A 起步与 JS 共同语法 · B 日常 TypeScript · C 进阶类型 · D HTML/CSS/DOM · E 浏览器机制、异步与数据 · F 工程化、测试与调试 · G React + TS · H Next.js 与基础全栈 · I 项目与部署（≥ 3 个递进项目）。详细拆分见 [CURRICULUM.md](CURRICULUM.md)。

## 5. 运行与判题（必须是真功能）

三种动作严格区分：**运行示例**（观察行为/网页）、**类型检查**（真实 TS 诊断）、**提交挑战**（按题目执行类型 + 行为验收）。

### 5.1 运行模式

| 模式 | 支持 | 执行位置 |
|---|---|---|
| `ts` 纯 TypeScript | 多文件 `.ts`、import/export、console 输出、异常、Promise/顶层 await 完成、停止与清理 | 沙箱 iframe 内创建的独立 Worker；超时与停止通过 `terminate()` 真正中断 |
| `dom` | `index.html` + `.css` + `.ts`，真实网页预览、元素/文本/属性/表单/事件测试 | 不透明来源沙箱 iframe 主线程 + 循环保护 |
| `react` | `.tsx`、React 19 + 正确类型定义、手动/即时预览、组件交互测试 | 同 `dom`，沙箱内预置 React 运行时与 Testing Library |

### 5.2 类型与行为测评

1. 类型检查使用真实 TS `Program`/`LanguageService` 的语法与语义诊断；转译只用于运行，不替代检查。
2. 每个练习配置真实需要的 `lib`、模块解析、虚拟 `.d.ts` 与依赖类型；编辑器诊断、提交判题与课程验证使用**同一 TS 版本（6.0.3）与同一配置构建函数**。
3. 默认 `strict`；特殊配置必须写入题目说明。
4. 支持：类型正例/反例（类型测试文件，含 `@ts-expect-error`）、运行时正常/边界用例、预期错误示例（文件 + 行 + 诊断码匹配，不接受“任意错误”）。
5. 空实现、错误返回、硬编码一条样例输出不能通过（多组测试 + 隐藏用例）。需要限制 `any`、类型断言、非空断言、`@ts-ignore` 的题目用 **AST 规则** + 类型反例，不靠源码关键词搜索。
6. 故意演示 any/断言/预期错误的示例按块声明例外。
7. 显示预期与实际、失败位置、原始错误；常见诊断附可靠中文解释，无法识别保留原文。
8. 状态互相独立；编辑后旧结果失效；提交冻结文件快照，结果绑定快照哈希。
9. 平台用于自学，不声称防作弊或提供不可篡改认证（测试与答案在客户端可见）。
10. 区分：平台自身测试（Vitest/Playwright）、课程内容构建校验（Node 静态检查 + 真实浏览器内跑完整判题流程）、浏览器内学生判题。构建时参考解通过 ≠ 学生通过。

## 6. 隔离与安全边界

- 主页面与服务器**从不** `eval`/`new Function` 执行学生代码。
- 学生代码运行在 `sandbox="allow-scripts allow-forms"`（**无** `allow-same-origin`）的 iframe 中，来源为不透明 `null`；页面自带 CSP：`default-src 'none'; script-src 'self' blob:; connect-src 'none'; form-action 'none'; base-uri 'none'` 等。
  - 结果（已在 Chromium、WebKit 实测）：无法读写主应用 localStorage/IndexedDB/cookie，无法访问父页面 DOM，fetch 与远程 import 被 CSP 拦截。
  - 不授予 `allow-popups`、`allow-modals`、`allow-top-navigation`、`allow-same-origin`。
- 通信：父页面为每个沙箱创建专属 `MessageChannel`，仅通过绑定该 frame 的 port 收发；不信任 `window` 上的 message；iframe 只接受来自 `window.parent` 的第一条结构合法的 init 消息；所有消息用 schema 校验并核对会话 id 与运行编号，过期运行的消息丢弃。
- 只向沙箱传运行所需的文件与测试，不传进度库、用户其他文件或同步密码。
- 课程需要的网络与存储使用**明确标注为模拟**的适配器（mock fetch fixtures、内存版 localStorage）；真实行为通过本地实验项目验证；不为演示解除隔离。
- 学生代码只在显式点击时运行；访问课页、粘贴代码、恢复草稿不会自动执行；语言诊断可自动更新。首期不支持运行他人分享的代码。
- 已知限制（如实说明）：
  - 普通 iframe 不是 CPU/内存硬隔离。实测 Chromium/WebKit 中沙箱 iframe 主线程死循环会冻结整个标签页，因此 DOM/React 模式对 `for/while/do-while/for-of/for-in` 插入经测试的时间型循环保护；其他形式的长时间同步计算仍可能需要关闭标签页。
  - 纯 TS 模式在 Worker 中运行，超时/停止调用 `terminate()`，已验证能中断同步死循环。
- 进度导入只接受结构化 JSON（大小上限、schema 校验、版本检查），从不执行其中内容。练习输出一律作为文本呈现。

## 7. 跨设备同步设计（追加要求 #2）

- **本地优先**：IndexedDB 永远是主存储，离线可用。
- **单用户密码**：部署时生成一个高熵随机密码交给学习者；服务器只保存其 SHA-256 哈希（环境变量 `SYNC_PASSWORD_HASH`），用常数时间比较。密码保存在本机浏览器（localStorage），可随时“退出同步”清除。
- **服务端**：Vercel Function `/api/sync`（GET 拉取 / PUT 推送），数据存于 Neon Postgres（免费额度）的一行 JSON 文档，带 `revision` 做乐观并发（CAS）。
- **合并**：按条目合并——练习/课时状态取“更进一步”的状态与较新的时间戳；草稿按 `updatedAt` 取新；冲突（409）时拉取、合并、重推。
- **安全边界**：同步密码与 AI 共用；HTTPS；请求体大小上限；不把密码放 URL。本方案适合单人使用，不是多用户账号体系。

## 8. 可选 AI 答疑（追加要求 #4）

- Vercel Function `/api/ai`，服务端读取 `AI_PROVIDER`（`anthropic` 或 `openai-compatible`）、`AI_API_KEY`、`AI_MODEL`、`AI_BASE_URL`；需要同步密码。
- 上下文：课时标题、当前步骤讲解、当前文件、最近诊断与输出、学习者问题。系统提示要求中文、先给思路、指出依据、不编造 API。
- 回答以安全 Markdown 渲染（不渲染原始 HTML）。未配置 key 时显示“未配置”。

## 9. 架构

```
content/ (受信任课程源：curriculum.yaml、课时 Markdown + 指令块、练习文件、测验)
  └─ scripts/build-content.ts → src/generated/ (目录 JSON + 每课 JSON，按需加载)
src/
  app/        路由与布局
  features/   catalog · lesson · exercise · quiz · progress · sync · ai · settings
  editor/     CodeMirror 6 封装（诊断/补全/悬停来自编译器 Worker）
  compiler/   TS 6.0.3 LanguageService Worker（@typescript/vfs、lib 与依赖 .d.ts、AST 规则、循环保护转换器、发射）
  runner/     沙箱宿主（iframe 生命周期、MessageChannel 协议、超时/看门狗）
  judge/      提交编排（快照、类型检查、类型测试、行为测试、规则）
  storage/    IndexedDB 仓库、版本迁移、导入导出、同步客户端
  shared/     沙箱协议 schema、判题结果类型
sandbox/      沙箱运行时（独立构建为经典脚本 + 内联 Worker）：模块链接、测试框架、React/Testing Library、模拟 fetch/localStorage
api/          Vercel Functions：sync、ai、health（逻辑在 server/，可单测）
labs/         本地实验项目（Vite 项目、项目 1–3、Next.js 实验），含起始/解答/测试
tests/e2e/    Playwright 端到端与课程验证
```

关键技术选择（理由见 [STATUS.md](STATUS.md) 的“决策记录”）：

- **TypeScript 6.0.3（锁定）**：npm `latest` 已是 7.0.2（Go 原生版），官方说明 7.0 不提供编程 API；浏览器内编译器必须用 JS 版 6.0。7.0 与 6.0 类型检查行为对齐。
- **CodeMirror 6** 而非 Monaco：移动端可用、体积小；诊断/补全/悬停全部来自同一个 TS 6.0.3 Worker，避免编辑器与判题版本不一致。
- **不引入 esbuild-wasm**：运行用的 JS 由同一 TS 版本逐文件发射（ESM），沙箱用 blob URL 链接模块（支持顶层 await）；React 依赖由沙箱运行时提供。
- React 19.3、React Router 8.5（声明式）、Vite 8.3、Vitest 5、Playwright 1.64、zod 4、idb 8。

## 10. 界面要求

- 左侧可折叠目录；中间是排版良好的交互式教材；代码块处直接操作；预览就近显示，可展开为工作区。
- 清楚的运行、停止、重置、检查、提示、答案按钮；执行与错误状态完整可见。
- 浅色/深色、字号调整；编辑器有足够高度。
- 键盘可操作、可见焦点；通过/失败不只靠颜色（图标 + 文字）。
- 窄屏不横向撑破；编辑器/编译器按需加载，未打开的示例不启动 Worker。
- 明确说明：进度保存在本机浏览器；启用同步后才跨设备。
- 存储失败、损坏数据、导入版本不兼容时明确报错，不假装保存成功。

## 11. 验收测试清单（每阶段运行）

- 课内改代码 → 运行 → 看到结果；代码变更后旧判题状态失效。
- 能运行但类型错误的答案不能通过类型挑战。
- 正确答案通过；至少一种错误行为与相关类型反例被拒绝。
- DOM 按钮/表单行为、React 状态更新确实发生。
- 纯 TS 无限循环可停止；切课/重跑清理资源与旧消息。
- 刷新后恢复代码。
- 导入非法或旧版进度不破坏现有数据。
- 生产构建中深层路由刷新、静态资源、Worker、类型库可加载。
- 沙箱不能访问主页面 DOM/存储；伪造来源的消息被拒绝。
- 桌面与窄屏无遮挡、溢出、空白编辑器或不可点按钮。
- 同步：两个独立浏览器上下文通过密码同步进度；错误密码被拒绝。

命令：`typecheck`、`lint`、`test`、`content:check`、`content:verify`、`test:e2e`、`build`（见 [AGENTS.md](../AGENTS.md)）。未运行的检查在 STATUS.md 中标为未验证。
